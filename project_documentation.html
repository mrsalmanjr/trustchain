Chapter 1: Introduction

The charity sector has long been plagued by issues of trust, transparency, and accountability. Donors often contribute to causes without knowing if their funds actually reach the intended beneficiaries or how they are spent. Conversely, legitimate Non-Governmental Organizations (NGOs) struggle to prove their credibility and verification status to potential backers.

TrustChain is a decentralized, transparent crowdfunding and charity platform designed to bridge this trust gap. By combining a modern web application stack with a secure database backend (Supabase) and public blockchain tracking (Ethereum Sepolia Testnet), TrustChain provides immutable proof of every single donation. In TrustChain, whenever a donor contributes, the donation is registered on a tamper-proof blockchain ledger, ensuring absolute transparency.

1.1 Literature Survey

Traditional charitable systems rely on centralized databases or manual accounting audits. Literature in philanthropy indicates several systemic problems:

  1. Lack of Transaction Tracking: Traditional platforms do not offer transactional tracking after the money leaves the donor's account.
  2. Intermediate Administrative Losses: Heavy administrative overheads reduce the actual money deployed on the ground.
  3. Syndicated Scams: Unverified NGOs posting fake campaigns.
  4. Existing Blockchain Solutions: Early Web3 charity applications suffer from high usability barriers (requiring MetaMask, Web3 wallets, and cryptocurrency). TrustChain addresses this by letting users pay using standard payment gateways (simulated via Razorpay) while automatically logging transactions to the Ethereum blockchain behind the scenes.

1.2 Challenges and Motivation

  • The "Black Box" Problem: Donors send money, but have zero visibility into final resource utilization.
  • Complex On-Chain UX: Forcing non-technical donors to handle gas fees, private keys, and cryptocurrency slows adoption.
  • Security & Verification: Lack of centralized SLA controls for verifying NGOs before they publish campaigns.
  • Database vs. Blockchain Sync: Ensuring rapid operations are handled by Supabase while transaction integrity is sealed on-chain.

1.3 Objectives of the Project

  • Ensure Immutable Transparency: Log every validated donation on the Ethereum Sepolia Testnet.
  • Dual-persistence Layer: Combine high-performance Supabase query capabilities with Ethereum smart contracts.
  • Role-Based Workspaces: Provide distinct, optimized portals for Donors, NGO Managers, and Administrators.
  • Verification Workflow: Implement a vetting pipeline where Admins review NGO documentation before certifying them.
  • Real-time Tracking: Enable donors to track their specific donation ID/transaction hash via a Blockchain Explorer.

1.4 Problem Definition

To design and build a secure, responsive, and intuitive dual-database charity platform (TrustChain) that enables secure donor registration, NGO credential submission, campaign review/management by administrators, and transaction logging on the Sepolia Testnet, satisfying both modern performance standards and cryptographic auditability.

Chapter 2: Proposed System

2.1 Proposed System Architecture & Block Diagram

TrustChain coordinates Presentation, Application, and Data layers seamlessly, combining a React frontend with a Node.js/Express backend that simultaneously writes to Supabase and the Ethereum blockchain.

Figure 2.1: System Block Diagram
  • Donor Module: Browse campaigns, make payments, view donation history, verify on ledger.
  • NGO Module: Submit registration documents, launch fundraising campaigns, upload utilization reports.
  • Admin Module: Verify NGOs, approve campaigns, monitor platform statistics and blockchain logs.

2.2 Description of Target Users

  • Donors: Individuals or corporate sponsors seeking transparent channels to fund humanitarian causes.
  • NGOs / Fundraisers: Vetted organizations that need a secure crowdfunding portal.
  • System Administrators: Platform operators responsible for audit checks, verification, and contract health monitoring.

2.2.1 Advantages

  • Hybrid Web2/Web3 UX: No web3 wallet installation required for donors.
  • Tamper-Proof Proofs: Transaction receipts contain unique block numbers and hashes verifiable on Etherscan.
  • Accountability Control: Campaigns must be reviewed and approved by Admins before going public.
  • Real-time Verification: Any donor can verify their donation on the public blockchain at any time.

2.2.2 Applications

  • Disaster relief mobilization.
  • Public healthcare crowd-funding.
  • Transparent educational scholarships.
  • Corporate Social Responsibility (CSR) auditing.

2.2.3 Scope (Boundary of Proposed System)

In-Scope: User authentication via secure custom JWTs; NGO profiles, campaign creation, and validation pipeline; Razorpay-simulated checkout; automated Ethereum contract transactions via Ethers.js; dynamic ledger explorer.

Out-of-Scope: Direct fiat-to-crypto exchanges, automated Solidity gas fee optimization, and direct multi-signature wallet integrations.

Chapter 3: Software Requirement Specification (SRS)

3.1 Overview of SRS

This Software Requirement Specification (SRS) defines the complete functionality, performance, and design constraints of the TrustChain Charity Platform. It acts as a formal agreement between developers and stakeholders to ensure the system meets all required transparency, tracking, and notification needs efficiently.

3.2 Requirement Specifications

3.2.1 Functional Requirements

  1. User Management: Registration, login, and profile modification with distinct roles (donor, ngo, admin).
  2. NGO Verification Flow: NGOs must upload a registration number and description. Admins must approve status before campaigns launch.
  3. Campaign Management: Vetted NGOs can post campaigns with target amounts, descriptions, and end dates.
  4. Donation Processing: Processes simulated checkout, records donation status, triggers on-chain logging, and returns the Sepolia transaction hash.
  5. Blockchain Explorer: Live querying of block numbers, timestamp confirmations, from/to wallet addresses, and transaction metadata.

3.2.3 Non-functional Requirements

  • Security: JWT-based session security, cryptographically hashed passwords (bcrypt), and schema-level row checks.
  • Performance: API responses under 200ms (cached or local DB), blockchain transaction verification within 15 seconds.
  • Responsiveness: Fully responsive CSS layout adjusting gracefully to mobile viewports.
  • Availability: 99% uptime on cloud hosting environment.

Chapter 5: Implementation

5.1 Proposed Methodology (Waterfall Model)

The development of TrustChain followed the Waterfall Model, a linear and structured approach consisting of distinct, sequential phases. Each phase was completed before moving on to the next to ensure systematic delivery.

5.2 Requirement Analysis

  • Identified key user roles: Donor, Admin, and NGO
  • Collected functional requirements: NGO verification pipeline, campaign management, donation processing, blockchain tracking
  • Analyzed non-functional requirements: performance, scalability, and security constraints
  • Ensured compatibility between JSON-RPC constraints (Sepolia gas costs, transaction speeds) and front-end usability

app.post("/api/auth/register", async (req, res) => { const { name, email, password, role, ngoParams } = req.body; const emailLower = email.toLowerCase().trim(); const hashedPassword = await bcrypt.hash(password, 10); if (isSupabaseConfigured) { const { data: existingUser } = await supabase .from('users').select('id').eq('email', emailLower).single(); if (existingUser) return res.status(400).json({ error: "Email already registered" }); const { data: newUser, error } = await supabase .from('users') .insert({ email: emailLower, name, role, password_hash: hashedPassword }) .select().single(); if (role === "ngo" && ngoParams) { const { error: ngoError } = await supabase.from('ngos').insert({ user_id: newUser.id, ngo_name: ngoParams.ngoName, verified: "pending" }); } const token = jwt.sign({ id: newUser.id, role: newUser.role }, JWT_SECRET, { expiresIn: "7d" }); return res.status(201).json({ user: userResponse, token }); } });

5.5 Blockchain Integration (blockchain.ts)

import { ethers } from "ethers"; export let provider: ethers.JsonRpcProvider | null = null; let wallet: ethers.Wallet | null = null; let contract: ethers.Contract | null = null; if (isBlockchainConfigured) { provider = new ethers.JsonRpcProvider(process.env.BLOCKCHAIN_RPC_URL); wallet = new ethers.Wallet(process.env.BLOCKCHAIN_PRIVATE_KEY!, provider); contract = new ethers.Contract( process.env.BLOCKCHAIN_CONTRACT_ADDRESS!, ["function recordDonation(string,string,uint256) public"], wallet ); } export const recordDonationOnChain = async ( donationId: string, campaignId: string, amount: number ): Promise<string> => { const tx = await contract!.recordDonation(donationId, campaignId, Math.floor(amount)); const receipt = await tx.wait(); return receipt.hash; }; export const getTransactionDetails = async (txHash: string) => { const receipt = await provider!.getTransactionReceipt(txHash); const block = await provider!.getBlock(receipt!.blockNumber); return { blockNumber: receipt!.blockNumber, timestamp: new Date(block!.timestamp * 1000).toISOString(), blockHash: receipt!.blockHash, from: receipt!.from, to: receipt!.to }; };

Chapter 7: Results and Discussions

The TrustChain application was successfully developed and thoroughly tested. The application meets all core objectives and functional requirements defined in scope.

  • User Registration/Login: Donors, admins, and NGOs securely register and login using role-based authentication with proper data mapping between the database and frontend.
  • Donor Dashboard: Donors can browse campaigns, make donations, and immediately verify their transaction hash on the Ethereum Sepolia network via the built-in ledger explorer.
  • NGO Campaign Management: Verified NGOs can create campaigns, track raised amounts, and post utilization reports to maintain transparency.
  • Admin Dashboard: Admins have full control to approve/reject NGO registrations and campaign proposals, with access to live blockchain status metrics.
  • Live Blockchain Integration: The platform uses Ethers.js to query real transaction receipts from the Ethereum Sepolia testnet, providing genuine block numbers, timestamps, and wallet addresses.

7.1 Conclusion

TrustChain was successfully built, tested, and integrated with the Ethereum Sepolia network and the Supabase relational database. Key achievements include:

  • Role-based login system with dedicated dashboards for Donors, NGOs, and Admins.
  • Seamless dual-persistence: Supabase for fast queries, Ethereum for immutable audit trails.
  • Every donation is cryptographically sealed on a public blockchain, verifiable by anyone at any time via Sepolia Etherscan.
  • The NGO verification pipeline ensures only authenticated organizations can raise funds.
  • Secure, responsive web-based interface developed using the modern TypeScript/React/Node stack.

7.2 Future Scope

  • Layer 2 Gas Optimization: Integrating Arbitrum or Polygon to reduce transaction fee overhead significantly.
  • Decentralized Document Storage: Using IPFS to store NGO certificates, making them tamper-proof and verifiable.
  • Mobile Application: Developing an Android/iOS app for broader donor accessibility.
  • Automated Yield Strategies: Smart contracts to put idle campaign funds to work in secure DeFi vaults.
  • Multi-language Support: Enable regional languages for improved accessibility in tier-2 and tier-3 cities.
  • AI-based Fraud Detection: Machine learning models to detect suspicious donation patterns and fraudulent NGO registrations.
